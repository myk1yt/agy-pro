# agy-pro Multi-Model Fanout Swarm Engine (`agy pro fanout`)

The **Fanout Swarm Engine** is a high-assurance, multi-model evaluation and reconciliation system built into `agy-pro`. It enables engineers and leadership (VP of Engineering / Arbiter) to dispatch tasks (code review, security audits, architectural plan evaluations, deep research, and technical brainstorming) across multiple heterogeneous LLMs in parallel under strict double-blind isolation.

---

## 1. Architectural Principles

```
                                  +-----------------------+
                                  |   VP / User Invocation|
                                  |    (agy pro fanout)   |
                                  +-----------+-----------+
                                              |
                   +--------------------------+--------------------------+
                   |                          |                          |
                   v                          v                          v
          [Seat 1: OpenAI]           [Seat 2: DeepSeek]         [Seat 3: Anthropic]
         (Double-Blind Box)         (Double-Blind Box)         (Double-Blind Box)
                   |                          |                          |
                   | Tool Loop:               | Tool Loop:               | Tool Loop:
                   | read_file, grep, glob    | read_file, grep, glob    | read_file, grep, glob
                   | (Sandbox Guarded)        | (Sandbox Guarded)        | (Sandbox Guarded)
                   v                          v                          v
             [Findings #1]              [Findings #2]              [Findings #3]
                   +--------------------------+--------------------------+
                                              |
                                              v
                              +-------------------------------+
                              |    Reconciliation Engine      |
                              |  - Cross-model verification   |
                              |  - Consensus clustering       |
                              +---------------+---------------+
                                              |
                        +---------------------+---------------------+
                        |                                           |
                        v                                           v
               [CONFIRMED Issues]                          [DISPUTED Issues]
             (Identified by >= 2)                        (Single-model Blocker/High)
                        |                                           |
                        +---------------------+---------------------+
                                              |
                                              v
                              +-------------------------------+
                              | VP Arbiter Synthesis Report   |
                              |  - summary.json               |
                              |  - reconciliation.md          |
                              |  - Individual Seat Reports    |
                              +-------------------------------+
```

### 1.1 Strict Double-Blind Isolation
During swarm execution, every seat runs independently in its own isolated goroutine. No model receives intermediate thoughts, prompts, tool outputs, or hypotheses generated by any other model. This completely eliminates confirmation bias and groupthink.

### 1.2 Zero Secret Leakage
- **No Secret Persistence**: Registries, state records, logs, and artifacts **never store API keys or plaintext secrets**.
- **Indirection via Env Var Names**: Providers declare only the environment variable name (`apiKeyEnv: "OPENAI_API_KEY"`).
- **Built-in Redactor**: Every string logged or emitted into artifacts passes through a multi-layer regex redactor masking known secrets, bearer tokens, and `sk-*` shapes.

### 1.3 Pure Standard Library
The engine is written in standard library Go 1.22+ (`net/http`, `encoding/json`, `os/exec`, `path/filepath`), ensuring cross-platform portability on Windows, macOS, and Linux without external dependency bloat.

## 2. Provider Registry Management

The registry lives at `~/.agy-pro/providers.json` (overridable via `AGY_PRO_PROVIDERS`).

### 2.1 Schema Definition
```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "defaults": {
    "n": 3,
    "timeoutSeconds": 120,
    "maxTurns": 10,
    "tools": "read,search"
  },
  "providers": [
    {
      "name": "openai",
      "baseURL": "https://api.openai.com/v1",
      "apiKeyEnv": "OPENAI_API_KEY",
      "models": [
        {
          "id": "gpt-4o",
          "family": "openai",
          "tags": ["flagship", "tools", "coding"],
          "contextLength": 128000,
          "maxOutputTokens": 4096,
          "capabilities": {
            "supportsTools": true,
            "allowedTools": ["read_file", "list_dir", "grep", "glob"],
            "supportsVision": true,
            "supportsVideo": false,
            "supportsThinking": false
          }
        }
      ]
    }
  ]
}
```

### 2.2 Model Capabilities
- `contextLength` (int): Total token window of the model.
- `maxOutputTokens` (int): Injected into `max_tokens` request body.
- `capabilities.supportsTools` (bool): Whether the model accepts OpenAI-compatible tool/function calling schemas. When `false`, the engine falls back to direct prompt mode without passing tools.
- `capabilities.allowedTools` ([]string): Restricts which tools this specific model is allowed to run.
- `capabilities.supportsThinking` (bool): Injects reasoning mode parameters when supported (e.g. `reasoning_effort`).

### 2.3 Interactive Setup Wizard (`agy pro fanout --setup`)
Run `agy pro fanout --setup` to configure providers interactively in the terminal:
1. Provider Name & OpenAI-compatible Base URL.
2. API Key environment variable name & optional live key input.
   - On Windows, automatically sets the key to the User Environment using `[System.Environment]::SetEnvironmentVariable`.
3. Model ID, Family, Context Length, and Max Output Tokens.
4. Model Capabilities: Function Calling, Allowed Tools, Vision, Video, and Thinking mode.
5. **Live Connection Probe Test**: Immediately issues a test ping to verify credentials and endpoint latency:
   - Success: `✅ Connection and basic call test succeeded (latency: 142ms)`
   - Failure: Displays HTTP code and response body, opening an **interactive correction loop** allowing immediate live adjustments to Base URL, API Key, or Model ID without restarting the wizard.

## 3. CLI Command Reference

```bash
agy pro fanout [options]
```

| Flag | Default | Description |
|---|---|---|
| `--task <name>` | `review` | Task preset: `review`, `security`, `plan-audit`, `research`, `ideas`, `custom`. |
| `--prompt <text>` | `""` | Inline prompt text passed to the swarm. |
| `--prompt-file <path>` | `""` | File path containing prompt text, or `-` for stdin. |
| `--n <count>` | `3` | Number of distinct seats/models to evaluate. |
| `--models <list>` | `""` | Comma-separated model filters (e.g. `openai/gpt-4o,deepseek/deepseek-chat`). |
| `--root <dir>` | `.` | Working workspace root directory for tool execution. |
| `--tools <list>` | `read,search` | Allowed tools. Read-only by default; `write` and `exec` require explicit opt-in. |
| `--max-turns <n>` | `10` | Maximum agentic tool iterations per model. |
| `--timeout <sec>` | `120` | Swarm timeout in seconds. |
| `--out <dir>` | `./reports/fanout/<ts>` | Output directory for seat reports and reconciliation matrix. |
| `--json` | `false` | Emits machine-readable `summary.json` directly to stdout. |
| `--setup` | `false` | Runs the interactive provider configuration wizard. |

## 4. Swarm Execution & Family Rotation

To ensure unbiased evaluation, model families must not overlap within a run, and consecutive runs should rotate through available model providers.

1. **Rotation State (`~/.agy-pro/state-fanout.json`)**:
   Tracks the families selected in previous runs.
2. **Selection Algorithm**:
   - Discovers all enabled models whose `apiKeyEnv` is populated.
   - Groups models by family (`openai`, `anthropic`, `deepseek`, `llama`, `qwen`, `mistral`).
   - Prioritizes families that were **not** used in the most recent run.
   - Selects the flagship/best model from each distinct family until `N` seats are populated.

## 5. Agentic Tool Sandbox & Security Guards

Each model can autonomously explore the workspace using standard tools:
- `read_file`: Line-numbered, sliceable file content reader.
- `list_dir`: Directory tree explorer with depth limits.
- `grep`: Regex-based codebase pattern search.
- `glob`: Wildcard file path resolution.
- `write_file`: (Opt-in only via `--tools write`) Atomic file write with overwrite protection.
- `run_command`: (Opt-in only via `--tools exec`) Subprocess execution with strict timeouts.

### 5.1 Directory Traversal Guard
Every tool call is validated by `agenttools.ResolveSafePath(root, path)`. Attempts to escape the `--root` boundary (via `../`, absolute paths outside root, or symlink pivots) are immediately rejected with an access-denied error.

### 5.2 Tool Audit Logging
All tool invocations and returned payloads are logged to `~/.agy-pro/logs/fanout-<timestamp>.jsonl` with seat ID, duration, and redactor scrubbing.

## 6. Fault Tolerance & Failover Protocol

When an individual model call fails (due to HTTP 401/402/429/5xx, rate limits, credit exhaustion, or timeout), the engine executes a strict 3-step failover cascade:

```
[Call Fails: Timeout, 429, 5xx]
       |
       v
Step 1: Check Registry for Alternate Provider offering IDENTICAL Model ID
       |
       +---> [Found] ----> Retry with Provider B (Same Model)
       |
       +---> [Not Found / Failed]
                   |
                   v
Step 2: Check Registry for Alternate Model from an UNUSED Family
       |
       +---> [Found] ----> Retry with Model C (New Family)
       |
       +---> [Not Found / Failed]
                   |
                   v
Step 3: Mark Seat Degraded (`degraded: true`) & Exclude from Quorum
       |
       +---> Swarm proceeds with surviving seats
```

## 7. Reconciliation Engine & VP Arbiter Synthesis

After all seats complete their investigations, the Arbiter Reconciliation Engine parses and cross-examines all findings.

### 7.1 Consensus Classification
- **`[CONFIRMED]`**: Identified by **2 or more models**. High confidence finding; recommended for immediate engineering action.
- **`[DISPUTED]`**: Identified by **only 1 model**, but classified as `BLOCKER` or `HIGH` severity. Flagged for mandatory VP (Arbiter) verification.
- **`[OBSERVATION]`**: Identified by 1 model with `MEDIUM`, `LOW`, or `INFO` severity. Tracked in backlog.

### 7.2 Generated Artifacts
Under `--out DIR` (default `./reports/fanout/<ts>/`):
1. `seat-<n>-<provider>-<model>.md`: The complete raw output and tool trajectory of seat `n`.
2. `summary.json`: Comprehensive machine-readable report with metadata, seat performance, failovers, and issue clusters.
3. `reconciliation.md`: Executive synthesis markdown containing:
   - Consensus & Reconciliation Matrix
   - Detailed Findings Breakdown with file locations
   - **VP Arbiter Decision Log**: Interactive checklist:
     ```markdown
     - [ ] **ACCEPT** / [ ] **DISMISS** : `ISSUE-001` (BLOCKER) - SQL Injection in auth
     ```
