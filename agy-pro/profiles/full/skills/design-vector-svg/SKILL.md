# Design Vector SVG (수학적 인라인 SVG 조판)

코드로 그리는 SVG가 "대충 비슷하게"가 아니라 **수학적으로 정확하게**
박스·텍스트·색상을 배치하도록 하는 조판 규격. 텍스트가 박스를 뚫고
나가거나, 색상이 탁하거나, 요소가 겹치는 문제를 **사전 계산**으로
원천 차단한다.

> 전제: 이 스킬의 산출물(SVG)도 `design-core-harness`의 시각 검증
> 루프 대상이다. SVG는 브라우저에서 즉시 렌더링 가능하므로
> `visual_qa.js`로 캡처해 4대 결함(잘림/겹침/플레이스홀더/대비)을
> 대조한다.

---

## 1. 뷰포트 엄격 규격 (680px Fixed Viewport)

모든 인라인 SVG는 **가로 680px 고정**으로 시작한다. 높이(H)는 콘텐츠에
따라 자유지만, 요소 배치의 모든 계산 기준은 680px 가로 좌표계다.

```html
<svg viewBox="0 0 680 H" width="100%" role="img" aria-label="...">
  <!-- H는 실제 콘텐츠 높이로 교체 -->
</svg>
```

### 1.1 뷰포트 규칙

1. `viewBox="0 0 680 H"`, 첫 두 값은 반드시 `0 0 680`.
2. `width="100%"`, 컨테이너 폭에 따라 리사이즈되고, 내부 좌표는 항상
   680 기준으로 유지된다.
3. `role="img"` + `aria-label`, 접근성용 텍스트 설명을 필수로 넣는다.
   (SVG 내부 `<text>`는 스크린 리더가 읽지 못하는 경우가 많다.)
4. 외부 CSS/폰트에 의존하지 않도록 폰트는 시스템 폴백 스택을 명시한다.
5. 높이 H는 모든 요소의 최저 `y`(디센더 포함) + 하단 패딩으로 계산한다.
   요소를 배치한 뒤 "그냥 넉넉히 200" 같은 추정 높이는 금지.

### 1.2 좌표계 기준

- 왼쪽 여백: **20px** 기준 (0에서 시작하지 않는다)
- 기본 배치 유닛: 20px 그리드 스냅 (요소 좌표를 20 단위로 정렬해
  간격 불균일을 방지)
- 텍스트 기준선(baseline)은 `dominant-baseline`으로 명시한다:
  - 박스 중앙: `dominant-baseline="central"`
  - 박스 하단 정렬 라벨: `dominant-baseline="text-after-edge"`

## 2. 문자열 픽셀 폭 실측 공식 (String Width Measurement)

텍스트가 박스를 뚫고 나가는 현상을 막기 위해, **SVG 코드를 쓰기 전에**
모든 문자열의 픽셀 폭을 아래 공식으로 계산한다.

### 2.1 폭 계산 공식 (Body 13px 기준)

| 문자 종류 | 단위 폭 | 예시 |
|-----------|---------|------|
| 라틴/숫자/공백 | 글자 수 × **6.5px** | `"Settings"` (8자) → 52px |
| 한글/CJK/전각 | 글자 수 × **13px** | `"설정 화면"` (4자) → 52px |
| 혼합 문자열 | (라틴 수 × 6.5) + (CJK 수 × 13) | `"설정 Settings"` → 4×13 + 8×6.5 = 104px |

> 이 값은 **13px 본문 기준**. 폰트 크기가 달라지면 비례 확장한다:
> `폭 = 글자수 × 6.5 × (실제px / 13)` (라틴), 동일 비율로 CJK.

### 2.2 텍스트 폭 안전 계산 순서

1. 문자열을 라틴/숫자 그룹과 CJK 그룹으로 분리해 각각 카운트한다.
2. 각 그룹 폭을 합산해 **총 텍스트 폭**을 구한다.
3. 박스 내부 폭이 `총 텍스트 폭 + 좌우 패딩(최소 +20px씩)`보다 큰지
   검증한다. (박스 폭 - 텍스트 폭) / 2 ≥ 20 이어야 한다.
4. 부족하면 (a) 박스 폭 확장 → (b) 폰트 축소 → (c) 문자열 축약 순으로
   해결한다.

### 2.3 하드 한도

- **박스 좌우 패딩 최소 +20px**, 텍스트와 박스 테두리 사이 여백은
  어떤 경우에도 20px 미만으로 줄이지 않는다. (좌우 각각)
- 줄바꿈이 필요한 긴 문자열은 `<text>`를 여러 `<tspan>`으로 나눠
  배치한다. 한 `<text>`에 680px를 넘는 단일 줄을 넣지 않는다.
- 권장 최대 텍스트 줄 폭: **600px** (뷰포트 680 - 좌우 여백 40 - 안전 40)

### 2.4 줄 높이(Line Height) 계산

- 기본 줄 높이: 본문 13px 기준 **18px** (라인 갭 5px)
- 두 줄 이상일 때 블록 높이 = `줄 수 × 18px`
- 헤딩(16px 이상)은 줄 높이 = `폰트크기 × 1.4`

## 3. 9대 색상군 4단계 매트릭스 (9-Family Color Matrix)

각 색상군은 **50 / 600 / 800** 3단계를 사용한다. (4단계로 부르는 것은
"배경50 → 보더·강조600 → 텍스트800"의 3사용처 + 명도 체계를 합친
관례적 명칭이며, 필요 시 100을 배경 위 미세 구분으로 추가할 수 있다.)

| 색상군  | 배경 50      | 보더/강조 600 | 텍스트 800  |
|---------|--------------|---------------|-------------|
| Purple  | `#faf5ff`    | `#9333ea`     | `#6b21a8`   |
| Teal    | `#f0fdfa`    | `#0d9488`     | `#115e59`   |
| Coral   | `#fff0eb`    | `#ee4f2e`     | `#9e341a`   |
| Blue    | `#eff6ff`    | `#2563eb`     | `#1e40af`   |
| Green   | `#f0fdf4`    | `#16a34a`     | `#166534`   |
| Amber   | `#fffbeb`    | `#d97706`     | `#92400e`   |
| Red     | `#fef2f2`    | `#dc2626`     | `#991b1b`   |
| Pink    | `#fdf2f8`    | `#db2777`     | `#9d174d`   |
| Gray    | `#f9fafb`    | `#4b5563`     | `#1f2937`   |

### 3.1 사용처 규칙 (역할 고정)

| 역할 | 단계 | 규칙 |
|------|------|------|
| 박스/영역 배경 | **50** | 초연한 파스텔 톤. 흰 배경 위 은은한 영역 구분용 |
| 테두리·강조선·액센트 도형 | **600** | 고대비 스트로크. 흐릿한 중간톤 금지 |
| 텍스트 | **800** | 50 배경 위 WCAG AAA 가독성 확보용 |

> ⚠️ 600을 배경으로, 800을 보더로 쓰는 **역할 역전**은 금지된다.
> 50은 배경 전용, 600은 라인/도형 전용, 800은 텍스트 전용이 기본.
> (단, 800 텍스트가 놓일 박스는 반드시 50 계열 배경이어야 대비가
> 보장된다.)

### 3.2 대비 보장 (WCAG AAA)

- **텍스트(800)는 반드시 배경 50 위에만** 배치한다. 아래 조합은
  전부 WCAG AAA(7:1 이상)를 만족하는 설계다.
  - 예: Purple `#6b21a8` on `#faf5ff`, Gray `#1f2937` on `#f9fafb`,
    Amber `#92400e` on `#fffbeb`
- 600 보더/도형 위에 텍스트를 직접 올리지 않는다. (600은 배경 대비
  AAA를 보장하지 않음, 강조 표시용)
- 백색 텍스트(#fff)는 **600 이상의 짙은 채색 배경 위에서만** 사용한다.
  (예: `#9333ea` 박스 위 흰 텍스트는 4.6:1 → 대형 텍스트 한정 허용)

## 4. 복잡도 예산 (Complexity Budget)

인지 부하를 통제하기 위해 다이어그램 하나에 아래 예산을 적용한다.
예산 초과는 설계 실패로 간주하고 **구조 단순화**부터 시작한다.

| 항목 | 한도 | 위반 시 조치 |
|------|------|--------------|
| 노드(박스/도형) 수 | **최대 15개** | 그룹핑(하위 노드를 1개 컨테이너로) 또는 단계 분리 |
| 색상군 수 | **최대 3개** | 주 색 1 + 보조 색 1 + Gray(중립) = 기본 권장 구성 |
| 텍스트 줄 수(전체) | **최대 25줄** | 불필요 라벨 제거, 범례 활용 |
| 화살표/연결선 | 노드당 평균 ≤ 2 | 교차 최소화 재배치 |

### 4.1 색상군 선택 규칙

- **주 색 1개**: 도식의 핵심 의미 (예: Blue = 데이터 흐름)
- **보조 색 1개**: 대비 의미 (예: Coral = 위험/강조 경로)
- **Gray**: 중립 노드·배경·라벨용, 색상군 카운트에서 제외해도 된다.
- 노드 내부 채움은 50, 테두리는 600, 라벨 텍스트는 800으로 동일
  색상군 3단계를 사용한다 → 색상 3종을 써도 시각적으로 정돈된다.

## 5. 조판 절차 (워크플로)

```text
① 목적/메시지 정의 ──▶ ② 노드·연결 구조 스케치 (≤15 노드)
      │                        │
      ▼                        ▼
④ 색상군·폭 계산 적용 ◀── ③ 텍스트 확정 (라벨 문자열 고정)
      │
      ▼
⑤ SVG 코드 생성 (viewBox="0 0 680 H")
      │
      ▼
⑥ 렌더링 캡처 + 4대 결함 대조 (design-core-harness 루프)
      │
      ▼
⑦ 통과 시 산출물 확정 / 실패 시 ③~⑥ 반복
```

### 5.1 실전 체크리스트 (SVG 생성 전후)

- [ ] `viewBox="0 0 680 H"` 준수, H는 계산값
- [ ] 모든 라벨 문자열의 픽셀 폭을 §2 공식으로 계산해 박스 폭 검증 완료
- [ ] 박스 패딩 좌우 각각 ≥ 20px
- [ ] 노드 ≤ 15, 색상군 ≤ 3 (Gray 제외 가능)
- [ ] 텍스트는 전부 색상군 800, 배경은 50, 보더/강조는 600
- [ ] 백색 텍스트는 짙은 600+ 배경 위에만
- [ ] `role="img"` + `aria-label` 포함
- [ ] 좌표 20px 그리드 스냅, 0 좌표 회피(최소 20px 여백)

## 6. 실전 예제 (아키텍처 2박스 도식)

아래는 680px 뷰포트에 Blue/Gray 2색상군을 사용한 간단한 예시다.
(실제 산출물은 검증 루프 후 확정)

```html
<svg viewBox="0 0 680 120" width="100%" role="img"
     aria-label="요청이 API 서버로 전달되는 흐름">
  <!-- 라벨: "Client 요청" = 7 latin × 6.5 + 2 cjk × 13 = 45.5 + 26 = 71.5px -->
  <!-- 박스 내부 폭 160px → 좌우 여백 (160-71.5)/2 = 44px ≥ 20 ✅ -->
  <rect x="30"  y="30" width="160" height="60" rx="10"
        fill="#eff6ff" stroke="#2563eb" stroke-width="2"/>
  <text x="110" y="60" text-anchor="middle" dominant-baseline="central"
        font-family="sans-serif" font-size="13" fill="#1e40af">Client 요청</text>

  <!-- 화살표 -->
  <line x1="190" y1="60" x2="250" y2="60" stroke="#4b5563" stroke-width="2"/>

  <!-- "API Server" = 10 latin × 6.5 = 65px, 박스 내부 폭 160 → 여백 47.5 ✅ -->
  <rect x="250" y="30" width="160" height="60" rx="10"
        fill="#f9fafb" stroke="#4b5563" stroke-width="2"/>
  <text x="330" y="60" text-anchor="middle" dominant-baseline="central"
        font-family="sans-serif" font-size="13" fill="#1f2937">API Server</text>
</svg>
```

> 계산 근거를 주석으로 남기는 습관이 중요하다. 나중에 요소를 추가할 때
> "여백이 왜 20 이상이어야 하는지"를 코드 주석에서 바로 알 수 있다.
