[Overview]
--------------------------------------------------------------------------------
Follow-up release for the full-screen setup TUI. It closes the defects found by
using the 0.10.9 TUI on a real Windows console and the gaps that release left
open: the model form gains the capability fields the registry already stored,
providers gain an in-place add and edit form whose only write path is the
exact-diff approval, and the form fields and the prompt editor gain a visible
caret with the standard editing keys. On a real console the arrow keys no
longer deadlock behind a window of mouse noise, a multi-line paste no longer
submits a form early, and the M4 approval gate can no longer be pushed off an
80x24 frame and answered blind. Credential masking is now one shared policy
with a recorded boundary instead of per-site patches, and the masking class is
closed. Every planted test credential moved into a concatenation-built
contract package. The live providers.json (md5 d17c70ad...) and state.json
(md5 2d6861d3...) were byte-unchanged across the whole mission.

Pool exclusion is now a user decision instead of a compiled-in rule. The
hardcoded k3 exclusion gives way to a list the user owns in providers.json,
one rule governs auto-seating and failover alike, the setup hub becomes the
only editor and the legacy settings panel a read-only view that routes to it,
and saved swarm seat presets become selectable by name. An excluded row is
marked in every list an agent reads, and the agent-facing rules point at that
marker instead of naming a family to avoid.

[Added]
- Model form capability fields: the add and edit form gains Thinking, Reasoning
  effort, Vision, and Video, in that order between the max-output row and the
  tool allow-list. Reasoning effort accepts a closed set (default, none, low,
  medium, high, xhigh, max); an empty value means the runtime default, and a
  value outside the set is refused with the cursor left on the failing field.
  A key-shaped value is refused by the secret check before the closed-set
  check and is never echoed. Edit prefills all four fields, the approval diff
  prints only the fields that changed, and an untouched edit still reads
  "(no field changes)". Stored flags for an existing model are visible instead
  of being passed through invisibly.
- The same four fields in the CLI twins: `model-add-json` and `model-update`
  print `supportsThinking`, `reasoningEffort`, `supportsVision`, and
  `supportsVideo` in the approval diff through the shared operand masker.
  `model-update` re-reads the registry after consent and re-verifies the
  presented diff before the write, so a change made while the approval was
  open refuses the write instead of being overwritten.
- Models list: each row carries the capability note from the stored flags
  (`vision`, `video`, `thinking(<effort>)`), and the sticky selection starts at
  none, so a verb pressed with no selection refuses ("Select a model row
  first.") instead of acting on the first row. The selected row is marked with
  a solid dot and the cursor is restored by row id after a mutation.
- Provider add and edit in the TUI: add takes a name, base URL, and key-env
  name; edit takes the base URL and key-env name only and renders the provider
  name as a fixed line no keystroke can reach. Both modes show the read-only
  providers.json defaults block and end at the M4 approval, which states the
  exact diff (`+ field: value`, `  field: before -> after`, or
  "(no field changes)") and the atomic 0600 write before anything is written.
  A missing, ambiguous, or unreadable provider refuses every save before an
  approval opens. The write is an in-place edit that leaves the model list and
  every key value untouched.
- Caret and text editing: Left and Right move the caret, Home and End jump,
  Delete removes forward, and typing inserts at the caret, on the form fields
  and in the prompt editor. The caret is drawn in-line: reverse video (SGR
  7/27) on the color tiers, a `|` marker with one-cell tail truncation on
  plain, and no application escape bytes on plain. No hardware cursor is used.
- The user-owned pool-exclusion list: providers.json carries
  `defaults.excludeModels`, a sibling of the still-reserved `excludeFamilies`.
  An entry names a provider (every model of it), a model id (that model under
  any provider), a provider/model pair (both sides must match), or
  `family:<name>`, which reproduces one of the built-in default entries
  exactly. The key absent or null applies the built-in default entry
  `family:k3`; an explicit empty list excludes nothing.
- Exclusion markers in the lists an agent reads: the swarm seat list and
  `agy pro models --all` mark an excluded row `excluded (exclusion list)`, and
  `agy pro models --json` carries the field `excluded` for the same row, so the
  user's decision is read from the inventory instead of inferred from a model
  name.
- Exclusion editing in the setup hub: `agy pro setup` edits the list behind the
  exact-diff approval modal, with a stale-base re-check, so the same gate that
  guards every other providers.json write guards this one.
- Seat presets by name: a saved swarm seat preset is selectable by name in the
  seat-selection grammar, alongside numbers, ranges, and p1/p2/p3. An unknown
  name-shaped token is refused by name at the interactive seat step.
- The integrations command surface: `agy pro integrations
  status|apply|retract|preset|adopt|rollback|repair` owns the rules, skills,
  plugins, hooks and statusLine slot the engine deploys. Every writing verb
  composes one plan, prints its exact diff and asks once (`y/N`); a
  non-interactive stdin must pass `--yes`, and the exit codes are 0 ok, 1
  runtime error or refusal, 2 usage error. Features are `statusline`, `hook`,
  `rules`, `plugins`, `skills`; presets are `native` and `tools` (`custom` is
  derived from the toggles and refused as an operand). The deployed `hook`
  document spells its one command field inline (`"command": "agy-tokens --hook"`,
  a shell and documents only `type`, `command` and `timeout`.
- The Integrations screen's action rows now carry per-row descriptions in all
  twelve languages, the picker rows (Preset, Rollback) are marked with `>>`, and a
  ten-topic manual browser opens from Help (Enter on the guide section): plain-
  language pages for every hub surface plus the CLI, scroll-clean at 80x24.
- The hub's Integrations screen and its hub row: per-feature intent plus engine
  posture, the preset picker, apply pending, retract all, adopt, rollback and
  repair, each behind the same single approval modal. The Integrations row lands
  at 9 and Exit moves to 10, so the footer advertises the list's `0`-prefix
  compose gesture.
- The rollback operand grammar: `agy pro integrations rollback` still restores
  `settings.json` from its snapshot chain, and `rollback <feature>`
  (`hook`, `rules`, `plugins`, `skills`) now restores that one content feature's
  pre-install deploy tree behind the same single consent while recording no
  `state.json` intent row, because restored bytes are not a posture the user
  stated. `rollback statusline` exits 2 and names the no-operand settings door,
  `rollback native|tools` (and `custom`) is refused because a whole posture has
  no single pre-install tree, and two operands is a usage error. The hub's
  Rollback row opens the same choice as a picker: `settings.json` plus the four
  content features.

[Fixed]
- Arrow keys dead on a real console: the reader returned "consume 0" forever
  when the first 32 queued records were all mouse noise, so every key behind
  them, arrows and digits alike, was unreachable. The reader now drains the
  noise window, the takeover clears ENABLE_MOUSE_INPUT, normalizes
  ENABLE_VIRTUAL_TERMINAL_INPUT, and sets ENABLE_WINDOW_INPUT, and Ctrl+C
  restores both console modes. The same full-window livelock is fixed in the
  older settings console reader.
- Multi-line paste submitting a form early: a pasted newline arrives as a CR,
  which mapped to Enter, submitted the form, and leaked the rest of the paste
  into the next surface including the approval modal. The reader now detects a
  paste burst and holds the interior newlines. Both gates also hold any answer
  typed within 25 ms of opening until the next key arrives, so a leaked
  remainder cannot confirm a registry write.
- The M3/M4 approval modal could sit entirely off-frame at 80x24 whenever the
  body filled the page, while the gate still swallowed every key, so the only
  providers.json write path could be approved blind. The composer now reserves
  the rows the modal, the message and the footer need, and the modal replaces
  the body instead of falling off the frame.
- The 105-cell base footer wrapped at 80 columns and cost a row the painter
  could not erase; the legend is now fitted to the width.
- Approval summaries and message lines are clamped to the frame width at the

- The remote model-list decode strip now removes the full Cc and Cf classes

[Overview]

Full-screen setup TUI for agy-pro: `agy pro setup` is now the single door to an
interactive configuration surface that covers everything the agy pro features
need, so nothing has to be configured inside agy. On a raw-console host the
command opens the TUI (banner splash, first-run language screen, then the hub);
on a non-console host (pipe, non-Windows TTY, mintty) it runs the existing
line-mode wizard byte-identically, so scripted callers are unaffected. `agy pro
setup --wizard` forces the classic wizard on any host, and any other setup
argument fails closed with the masked operand, the help text, and exit code 2.
Bare `agy pro help` advertises the TUI prominently. The hub manages providers,
per-model add/update/delete behind an exact-diff approval gate (the only write
path to providers.json), fanout presets, prompt authoring, and settings. New CLI
twins `agy pro settings providers model-add-json|model-update|model-delete`
mirror the model ops. The TUI ships with 12 UI languages, honest RTL scope for
Arabic (logical-order text plus mirrored layout; no bidi shaping, no mid-string
truncation, no inline RTL editing), a four-tier color banner (truecolor / 256 /
16 / plain ASCII, NO_COLOR and AGY_PRO_COLOR aware), a persisted launcher-menu
toggle (AGY_LAUNCHER still wins entirely when set), and fanout prompt authoring
(prompts/ directory plus AGY_PRO_PROMPTS_DIR and AGY_PRO_SEAT_PREAMBLE). The
fanout run config now resolves through a documented ladder: CLI flag >
AGY_PRO_FANOUT_PRESET / active preset (--preset or the store default) >
providers.json defaults block (consumed, read-only) > engine default, with a
one-time stderr notice when the stored defaults drift from the engine defaults
(timeoutSeconds 120 vs 300 is surfaced, never silently normalized).

[Overview]

Provider-seat tool parity (B4) for the fanout swarm, all default OFF: partition
units can now opt into write per plan unit, and provider seats can be given two
run-level network tools. A plan unit carrying `"write": true` gives that unit's
PROVIDER seat `write_file`/`replace_in_file`, confined by the same lexical AND
symlink-resolved scope rule as reads (refusal is error-shaped and model-visible);
there is no CLI-wide write switch, native partition seats stay refused, and
`run_command` remains OUT (held for a separate user decision). The repeatable
`--allow-host` flag enables `read_url_content` (GET only, https only with a
loopback http exception, no headers or auth, redirect cap 3 with per-redirect
re-validation, 512 KiB body cap, text content types only; an empty allow-list
refuses every call), and `--search-endpoint` / `--search-key-env` enable
`search_web` (endpoint template with one `{query}` placeholder, key referenced
by env-var NAME only and read at call time into the Authorization header, honest
not-configured error when no source is configured, never a fake result). Every
capability defaults OFF: with no allow-list and no search source the wire stays
byte-identical to a pre-B4 run. Which provider models gain these tools in the
live registry (`providers.json`) is presented for explicit user approval after
convergence and is not part of this release. Docs updated: `agy-pro/docs/fanout.md`,
`agy-pro/docs/swarm-hybrid.md`, and the `agypro_swarm` plugin docs.

[Added]
- Per-unit write opt-in for partition mode: the plan `Unit` gains an optional
  `write` field (JSON `"write"`, default false). A `write: true` unit's provider
  seat gets `AllowWrite` and a write-capable tool list via a deliberate per-unit
  carve-out of the run-level read-only clamp; a `write: false` unit carries no
  write tools. Write confinement reuses the read scope boundary: the target's
  lexical path AND its symlink-resolved path (closest-existing-ancestor
  resolution for not-yet-existing files) must both stay inside the unit scope,
  refused error-shaped through the same seeded redaction machinery as reads.
  Native partition seats stay refused (also for write units) before any
  subprocess spawns; written output paths ride the existing claim walk and the
  named-conflict policy (two write units claiming one path fail the run).

[Overview]

This release permanently eliminates the Go Language Server TLS handshake error
("client sent an HTTP request to an HTTPS server") in src/gemini-quota.js.
Previously, when the Language Server was running on an HTTPS endpoint without
a CSRF token or when an RPC call returned an authentication failure (HTTP 401),
fetchLiveGeminiQuota attempted a plaintext HTTP fallback on the same port,
triggering Go Language Server TLS handshake errors in the console.
In this release:
1. When candidate ports respond over HTTPS (or TLS handshake succeeds),
   plaintext HTTP fallback is strictly blocked and the protocols loop breaks
   immediately for that port.
2. When no CSRF token is available (!csrfToken), unauthenticated Language Server
   RPC calls are gracefully skipped, preventing futile network requests, 401 logs,
   and TLS handshake issues while preserving honest fallback diagnostics.

--------------------------------------------------------------------------------
[Detailed Changes & Differences from 0.10.2]
--------------------------------------------------------------------------------

1. HTTPS Port Fallback Protection (src/gemini-quota.js)
   - Introduced confirmed HTTPS port detection (_detectedHttpsPorts):
     * When any response is received over HTTPS or socket.once('secureConnect')
       fires, the port is marked as HTTPS.
     * When proto === 'https' completes with an HTTPS response (whether 200, 401,
       403, or any HTTP status code) or TLS handshake succeeded, the protocols
       loop immediately breaks for that candidate port. Plaintext HTTP fallback
       is never attempted on confirmed HTTPS ports.
     * makeRpcRequest guards against plaintext HTTP calls to confirmed HTTPS ports,
       immediately rejecting with ERR_HTTP_BLOCKED_ON_HTTPS without socket emission.

2. Graceful Unauthenticated Probe Skip (src/gemini-quota.js)
   - When !csrfToken (no CSRF token found in CLI args or environment variables),
