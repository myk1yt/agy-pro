Version: 0.10.6
Release Date: 2026-10-15
Previous Version: 0.10.5

--------------------------------------------------------------------------------
[Overview]
--------------------------------------------------------------------------------
Native coexistence: registered external providers now run inside agy's own
native session, with no agent mediation, behind two per-session profiles the
user picks with `agy pro hybrid on p1|on p2`. Profile P1 ("picker coexistence")
lists externals in agy's own /model catalog on agy's own 11-tool engine with
zero settings writes; profile P2 ("subagent profile") attaches the full 13-tool
set including the subagent family and runs a subagent `inherit` on the external
session model. One session is one client path - a proven binary fact, not a
design choice. The release also ships the shared mesh/codec/settings core, a
wirecheck drift gate that fails closed to a native session, and M4 hardening of
the existing gateway bridge. Honest limits are stated plainly in the docs, not
hidden (see [Limits]).

[Added]
- Native-coexistence front doors: `agy pro hybrid on p1|on p2|off|status|check`
  plus the `AGY_PRO_HYBRID=p1|p2|off` launch override (env beats the persisted
  value). P1 execs the real agy behind a per-session `/v1internal` mesh via
  `CLOUD_CODE_URL` (externals in agy's own /model catalog on agy's own 11-tool
  engine, no settings file written). P2 execs agy in gemini mode via a
  per-session `--app_data_dir` + `GOOGLE_GEMINI_BASE_URL` (full 13-tool set
  incl. the subagent family, a subagent `inherit` runs on the external session
  model, externals selected at launch via the launcher picker or `--model`). A
  native/static id is served only if that exact id is in the registry (billed to
  the configured provider), else a clear 404 naming the model - never a silent
  substitution.
- Shared core: internal/mesh (per-spawn supervisor, ephemeral loopback port,
  health gate, lifetime tied to the child agy), internal/geminiwire +
  internal/wireadp + internal/openaiup (both wires, id-paired functionResponse,
  SSE framing), internal/agysettings (per-session app-data regime, managed-key
  ledger, byte-identical rollback), internal/hybrid (catalog composition:
  synthesized enums, agent_model_sorts membership, display_name, max_tokens
  floor, fail-closed collision policy).
- internal/wirecheck: per-profile canaries plus a version pin on the resolved
  real binary, and a GO/NOGO verdict that gates the launcher (NOGO => native
  fallback with a clear notice; version drift proceeds with a surfaced notice).
- Credential safety: provider keys resolved in-process by NAME only, never in
  the child env / logs / settings; the child env scrubs every `*_API_KEY`-shaped
  name plus the registry names; the P2 mesh authenticates the child with a
  per-spawn 64-hex nonce; agy's keyring bearer is received passively on P1 and
  discarded, never forwarded.

[Hardened]
- M4 gateway bridge (still the XOR, tool-less escape hatch on agy 1.3.5):
  streaming during tool turns, cross-turn cumulative usage on the synthesized
  answer, a main-child env scrub closing the known asymmetry, and a 32 MB
  outbound body cap that fails loudly without contacting the provider (never
  silently truncated).

[Limits]
- One session cannot have both the picker (P1) and subagents (P2); the user
  picks one per session.
- Per-subagent external model binding is impossible on agy 1.3.5; `inherit` is
  the mechanism.
- Subscription Gemini + externals in one picker needs the M1 relay
  (approval-gated), which is NOT in this release.
- The G8 TUI gate is 시각 미검증 (UNVERIFIED) pending the manual test script;
  the automated gates G4/G5/G6/G10 carry live print-mode evidence, and G11
  (auto-update restart) is NOT-TESTED with reason (no update was available to
  trigger).
- `go test -race` is not runnable on the dev machine (no C compiler) - an
  environmental degradation, not a PASS.

[Verification]
- `go build ./...`, `go vet ./...`, `go test ./... -count=1 -p 1`: 19 test
  packages ok, 0 FAIL (`profiles` has no test files).
- Live gates against real agy v1.3.5: G4 (P1 sandbox e2e), G5 (P2 sandbox e2e),
  G6 (one real-provider print run per profile; both live providers HTTP 200 on
  all four profile x provider cells), G10 (error classes 401/429/5xx/mid-stream
  + retry-storm detector; worst case 4 requests in any 40 s window vs a
  >10 threshold).

Version: 0.10.5
Release Date: 2026-10-14
Previous Version: 0.10.4

--------------------------------------------------------------------------------
[Overview]
--------------------------------------------------------------------------------
Swarm inside the agy TUI plus the launcher [2] hang fix. The hybrid swarm is now
reachable from inside an agy chat session through the `/agypro_swarm:swarm`
plugin slash command (numbered seats, cost-confirmed dry-run echo, artifact
findings in chat), the launcher [2] model picker no longer hangs the real agy
child (root cause: the picker handed the child a relay pipe as stdin while the
child's stdout was the console), and the profile config.json plugin map ships
in the object form agy's protojson parser accepts.

[Added]
- `/agypro_swarm:swarm` plugin command (plugins/agypro_swarm): an agent-mediated
  workflow that reads the combined inventory (`agy pro models --all`), collects
  template/seats/tools/timeout/task through numbered menus, echoes the resolved
  `agy pro swarm --dry-run` command with a per-seat cost note and an explicit
  go/no-go, then runs the real swarm and presents summary.json /
  reconciliation.md / seat-*.md findings in chat. Plugin commands are
  namespaced by agy's plugin system, so the invocation is
  `/agypro_swarm:swarm` (a plain `/swarm` is not a core command).
- skills/swarm/SKILL.md mirror so the workflow is discoverable from `/skills`
  and the model side (the same pattern as agypro_settings).

[Fixed]
- Launcher [2] hang: after the model picker the real agy child never rendered.
  Root cause (reproduced headlessly against a real hidden console): the picker
  read its selection through the shared stdin relay and handed the child the
  relay pipe as stdin; agy's TUI blocks reading a pipe stdin while its stdout
  is a console, so the session sat silent forever (0-byte language-server log).
  The picker now reads its line through the console path (multi-digit capable,
  nothing consumed until the line is complete), so the child inherits the
  console directly - the configuration every other route already used.
- Picker cancel/invalid feedback: an empty answer and an unparseable answer
  both state the outcome and the grammar instead of failing silently
  ("invalid selection ... (want a number 1-14, a range like 3-5, or a preset
  p1-p3); continuing with External Models (bridge)").
- Profile config.json plugins map: ships `{"<dir>": {"enabled": true}}` instead
  of a bare boolean, which agy's config parser rejected ("unexpected token
  true"), silently dropping every plugin enablement record.

[Security]
- The swarm dry-run echo no longer inlines the task prompt: when the prompt
  arrives via --prompt-file the echoed (and executed) fanout command references
  the file, so untrusted prompt text can never ride a copy-pasteable shell line.
  The command body labels the echo "information only - NEVER execute or paste",
  names the --prompt-file swarm form as the only real-run command, binds the
  shell-safe charset to EVERY interpolated operand (seats, template, --task,
  --tools, provider names, --root), confines --root to the workspace without an
  explicit confirmation, and warns that --tools bounds provider seats only
  while native seats run the agy default tool surface.

[Tests]
- Fail-without-fix pins: the console-path picker must leave the relay untouched
  (rel.Used() == false), a console timeout cancels with a message, every cancel
  states its outcome, the console line reader folds each record exactly once
  across ticks (slow typing), accumulates every text key including non-ASCII,
  honors repeat counts for text and Backspace, pairs UTF-16 surrogates, and
  consumes nothing on timeout; the file-path echo must reference --prompt-file;
  the profile config.json plugin values must parse as {"enabled": bool} with
  keys naming real plugin directories; the plugin lint pins the honesty label,
  XOR boundary, cost confirmation, dry-run-first, untrusted-data and
  shell-safety rules and the SKILL.md mirror.

Version: 0.10.3
Release Date: 2026-09-12
Previous Version: 0.10.2

--------------------------------------------------------------------------------
[Overview]
--------------------------------------------------------------------------------
This release permanently eliminates the Go Language Server TLS handshake error
("client sent an HTTP request to an HTTPS server") in src/gemini-quota.js.
Previously, when the Language Server was running on an HTTPS endpoint without
a CSRF token or when an RPC call returned an authentication failure (HTTP 401),
fetchLiveGeminiQuota attempted a plaintext HTTP fallback on the same port,
triggering Go Language Server TLS handshake errors in the console.
In this release:
1. When candidate ports respond over HTTPS (or TLS handshake succeeds),
   plaintext HTTP fallback is strictly blocked and the protocols loop breaks
   immediately for that port.
2. When no CSRF token is available (!csrfToken), unauthenticated Language Server
   RPC calls are gracefully skipped, preventing futile network requests, 401 logs,
   and TLS handshake issues while preserving honest fallback diagnostics.

--------------------------------------------------------------------------------
[Detailed Changes & Differences from 0.10.2]
--------------------------------------------------------------------------------

1. HTTPS Port Fallback Protection (src/gemini-quota.js)
   - Introduced confirmed HTTPS port detection (_detectedHttpsPorts):
     * When any response is received over HTTPS or socket.once('secureConnect')
       fires, the port is marked as HTTPS.
     * When proto === 'https' completes with an HTTPS response (whether 200, 401,
       403, or any HTTP status code) or TLS handshake succeeded, the protocols
       loop immediately breaks for that candidate port. Plaintext HTTP fallback
       is never attempted on confirmed HTTPS ports.
     * makeRpcRequest guards against plaintext HTTP calls to confirmed HTTPS ports,
       immediately rejecting with ERR_HTTP_BLOCKED_ON_HTTPS without socket emission.

2. Graceful Unauthenticated Probe Skip (src/gemini-quota.js)
   - When !csrfToken (no CSRF token found in CLI args or environment variables),
     unauthenticated Language Server RPC calls are gracefully skipped.
   - Sets auth failure diagnostics ('HTTP 401 (missing CSRF token)') without
     sending zero-benefit network requests that are guaranteed to fail with 401.

3. Test Suite Expansion (test/run-tests.js)
   - Added unit test: fetchLiveGeminiQuota should NEVER attempt plaintext HTTP
     fallback on a port that responded via HTTPS (asserts 0 clientError/TLS errors).
   - Added unit test: fetchLiveGeminiQuota should gracefully skip unauthenticated
     RPC probe when csrfToken is missing (asserts 0 requests made, clean auth_failure).
   - Test suite pass rate: 210 passed, 0 failed (100% pass rate).

4. Version Bump (package.json)
   - Bumped version to 0.10.3.

5. Zero External Dependency Invariant
   - Built purely with Node.js standard built-ins (http, https, crypto, child_process, fs, path).

Version: 0.10.2
Release Date: 2026-09-12
Previous Version: 0.10.1

--------------------------------------------------------------------------------
[Overview]
--------------------------------------------------------------------------------
This release fixes statusline badge wrapping behavior in hook and subprocess
environments (such as Antigravity CLI's statusLine integration). Previously,
when process.stdout.columns was unavailable or stdout was not a TTY, the formatter
fell back to an arbitrary 100-column width limit, causing normal badges containing
the Dashboard link (📊 대시보드) to wrap onto a second line with Dashboard isolated.
The formatter now defaults strictly to 1 single line in hook/subprocess/non-TTY
environments, and only wraps to 2 lines when terminal columns are genuinely
known and too narrow.

--------------------------------------------------------------------------------
[Detailed Changes & Differences from 0.10.1]
--------------------------------------------------------------------------------

1. Terminal Width Resolution & Non-TTY Single-Line Default (src/formatter.js)
   - Updated resolveBadgeWidth():
     * Respects process.env.COLUMNS when explicitly provided.
     * Evaluates process.stdout.columns ONLY when process.stdout.isTTY is true and
       positive finite columns are available.
     * Falls back to Infinity instead of 100 in non-TTY, piped, or hook subprocess
       environments.
   - Guarded wrapBadgeSegments() against non-finite or non-positive widths to ensure
     clean single-line rendering by default.
   - Prevents premature line breaks that previously pushed the Dashboard link segment
     down to line 2 during routine Antigravity statusLine invocations.

2. Test Suite Expansion (test/run-tests.js)
   - Added REQ-1f: Verified resolveBadgeWidth returns Infinity when COLUMNS is unset
     and stdout is not a TTY.
   - Added REQ-1g: Verified renderRealTimeBadge defaults to 1 single line in hook/
     subprocess (non-TTY) environments, retaining the Dashboard link inline.
   - Added REQ-1h: Verified renderRealTimeBadge wraps into 2 physical lines when
     stdout.isTTY is true and stdout.columns is narrow (< total width).
   - Test suite pass rate: 208 passed, 0 failed (100% pass rate).

3. Version Bump (package.json)
   - Bumped version to 0.10.2.

4. Zero External Dependency Invariant
   - Built purely with Node.js standard built-ins.

Version: 0.10.1
Release Date: 2026-09-12
Previous Version: 0.10.0

--------------------------------------------------------------------------------
[Overview]
--------------------------------------------------------------------------------
This release introduces real-time quota fallback and CSRF token discovery across
both the interactive terminal statusline (formatter.js) and the web dashboard
(html-report.js). When Language Server live quota is stale (>5m) or encounters
an authentication rejection (HTTP 401), the application seamlessly falls back
to local transcript rolling quota (rollingUsage: 5h and 7d sliding windows)
instead of freezing on outdated snapshot data.

--------------------------------------------------------------------------------
[Detailed Changes & Differences from 0.10.0]
--------------------------------------------------------------------------------

1. Environment Variable CSRF Token Discovery (src/gemini-quota.js)
   - Updated parseCommandLine() to inspect process.env.ANTIGRAVITY_CSRF_TOKEN
     and process.env.CSRF_TOKEN when --csrf_token / --csrf-token flag is absent
     from the process command line.
   - Preserves command-line arguments as first priority when explicitly present.
   - Solves the Language Server v0.2+ issue where the server process no longer
     exposes --csrf_token in its command-line arguments.

2. Cache Staleness & Diagnostics Flagging (src/gemini-quota.js)
   - In getCachedGeminiQuota(), the cache age is evaluated against a 5-minute TTL
     (STALE_RETRY_AFTER_MS = 300,000ms).
   - If the snapshot age exceeds 5 minutes, or if lastError.kind === 'auth_failure',
     the returned object is explicitly stamped with isStale: true and isFresh: false.
   - Enables upstream callers (statusline, hook runner, web dashboard) to
     differentiate between live fresh quota and obsolete/unauthenticated snapshots.

3. Statusline Seamless Fallback to Real-Time Rolling Quota (src/formatter.js)
   - In renderRealTimeBadge(), when geminiQuota is stale (isStale === true or
     lastError.kind === 'auth_failure') and badgeData.rollingUsage is available,
     the badge bypasses the frozen Language Server cache snapshot.
   - Renders live 5h and 7d quotas from local session transcripts using the
     rollingUsage metrics (remain5hPercent, remain7dPercent) annotated with '(est)'.
   - Retains backward compatibility: if rollingUsage is not provided, continues
     rendering the cached snapshot with staleness markers ('*' for stale, '!' for
     auth failure).

4. Web Dashboard Seamless Fallback (src/html-report.js)
   - In the client-side renderQuota(r, gq) renderer, checks whether geminiQuota is
     stale or auth-failed via isStaleGq.
   - When stale or auth-failed, falls back gracefully to rollingUsage ('r') to
     render live 5h and 7d quota cards with the ESTIMATE badge and real-time usage
     meters instead of displaying obsolete multi-hour-old data.

5. Version Bump (package.json)
   - Version updated from 0.10.0 (and legacy 0.0.1 in repository metadata) to 0.10.1.

6. Verification & Test Suite Expansion (test/run-tests.js)
   - Added unit test: parseCommandLine token discovery from ANTIGRAVITY_CSRF_TOKEN
     and CSRF_TOKEN with CLI priority preservation.
   - Added unit test: getCachedGeminiQuota staleness flagging (isStale: true) on
     age >= 5m or HTTP 401 auth_failure.
   - Added unit test: renderRealTimeBadge fallback to rollingUsage with '(est)'.
   - Test suite pass rate: 205 passed, 0 failed (100% pass rate).

7. Zero External Dependency Invariant
   - Strictly maintained zero external runtime dependencies using Node.js
     core modules only (fs, path, http, https, child_process).
